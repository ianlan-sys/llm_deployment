# 麒麟设备实机测试清单

拿到演示设备后按顺序执行。每一步都写了预期结果；与预期不符时记下现象，继续做后面的步骤，最后把“需要带回的材料”一并带回。

到目前为止，arm64 安装包只在 QEMU 模拟环境里验证过功能，**没有在真实的飞腾 / 鲲鹏设备和真实的麒麟系统上运行过**。下面标了“首次实测”的步骤是最可能出问题的地方。

## 准备

| 项目 | 说明 |
| --- | --- |
| 安装包 | 飞腾、鲲鹏选 `local-llm-demo-offline-arm64.tar.gz`；海光、兆芯选 amd64 包。连同 `.sha256` 文件一起拷贝 |
| 介质 | 可用空间 ≥ 4 GB 的 U 盘或移动硬盘（单个安装包约 1.5 GB） |
| 设备 | 麒麟 V10，4 核 CPU、8 GB 内存、20 GB 可用磁盘；有管理员（sudo）权限 |
| 时间 | 首次完整走一遍约 40 分钟 |

| # | 操作 | 预期结果 | 结果 |

| 3 | `tar -xzf local-llm-demo-offline-arm64.tar.gz && cd local-llm-demo-offline-arm64` | 解压无报错 | |
| 4 | `sudo ./check.sh`（首次实测） | 列出系统信息；记下所有 `[ 注意 ]` 行。脚本无法运行时见下方“常见拦截” | |
| 5 | 用登录桌面的用户执行 `sudo ./install.sh --install-docker --desktop --bind 127.0.0.1`（首次实测） | 约 3–10 分钟后显示“安装完成”、访问地址、用户名和**只显示一次的口令**（立即抄下） | |

## 常见拦截

- **脚本提示权限不够或被阻止**：麒麟 KySec 的执行控制拦截了脚本。`sudo getstatus` 查看状态；在“安全中心 → 应用控制与保护”把执行控制改为“警告”，或执行 `sudo setstatus softmode`，然后重试。涉密环境先取得安全管理员同意。
- **第 5 步停在“启动服务”或报服务未就绪**：运行 `sudo ./status.sh`，把输出保存下来。
- **`check.sh` 显示内存页大小为 64K**：这是尚未实测的内核配置，照常继续安装，重点观察第 5 步和第 8 步。

## 需要带回的材料

1. 安装目录下所有 `llmdemo-check-*.txt` 文件（不含口令和密钥）。
2. 第 8 步 `bench.sh` 的完整输出。
3. 任何失败步骤的 `sudo ./status.sh` 输出：`sudo ./status.sh > status.txt 2>&1`。
4. 上表“结果”一列，以及第 10 步的等待秒数。

## 判定

- **可以用本地模型现场演示**：第 1–16 步全部符合预期，且平均生成速度 ≥ 8 token/秒。
- **可以演示，但知识库改用 Mock**：功能步骤通过，平均生成速度低于 3 token/秒，或第 10 步等待超过 30 秒。
- **介于两者之间**（3–8 token/秒）：可以用本地模型，但演示前先把要问的问题各问一遍。
- **不能演示**：第 5、6、7 步任何一步无法通过。把材料带回后再排查。
